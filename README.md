# 日本史ならべ

日本の歴史のできごとと人物のカードを、年表にならべて学ぶ Web アプリです (小学 6 年生向け)。
小学校の社会で習うできごとと、中学受験でよく出るできごとを、区別せずにまぜて出します。
サーバーは不要で、ビルドした静的ファイルを置くだけで動きます。

- できごとのカード 5 枚を、年表に古い順 (左がむかし) にならべ、人物のカードを関係するできごとの下にならべる
- カードは、タップでえらんでタップで置くか、ドラッグで置く。置いたときに正しいかどうかが分かり、まちがいはカードがゆれて手札にもどる (ミスに数える)
- 全部ならべると、できごとのカードの上に年 (1185年、約1万6000年前〜 など) が出て、年表と解説でふりかえる
- 今日のチャレンジ: 日本時間の日付から、毎日 5 つのできごとを自動でえらぶ。同じ日はだれが開いても同じ
- 時代ごとの練習: 7 つの時代と「時代をこえて」(全部から)。ミス 3 回まででクリア。「つぎの 5つ」で続きのできごとに進む
- 年表ずかん: 全部のできごとを、時代ごとに年・人物・解説つきで見られる
- スタンプカード・ポイント・スズメカード (歴史のスズメ 20 種類)、Google ログインでの記録の保存は、[スズメの社会クイズ](../social-studies-quiz) と同じしくみ

## 使い方

```sh
npm install
npm run dev      # 開発サーバー
npm test         # テスト
npm run build    # dist/ に静的ファイルを出力
npm run preview  # ビルド結果の確認
```

## できごとと人物のデータ

| データ | 場所 |
|---|---|
| できごと (147 件) | `src/data/events.ts` |
| 人物 (125 人) | `src/data/people.ts` |
| 時代 (練習のステージ) | `src/data/eras.ts` |

できごとは 1 件ずつ、次のように書きます。

```ts
{
  id: 'kamakura', era: 'medieval', from: 1185, when: '1185年',
  title: '鎌倉幕府(かまくらばくふ)が 開かれる', people: ['yoritomo'],
  note: '源頼朝は、全国に守護(しゅご)と地頭(じとう)を置くことを…',
},
```

- `from` / `to` はならべる順を決める年。紀元前や「○年前」は負の数にする (およその値でよい)。縄文時代のような期間は `to` まで書く
- `when` はクリアしたときに出す表示。「1185年」「1831年ごろ」「約1万6000年前〜約2400年前」など
- `people` は関係する人物の id。大事な順に 3 人まで。人物は `people.ts` に足す
- ふりがなは `漢字(かんじ)` と半角かっこで書く (ふりがなは、かっこの前に続く漢字全体に付く)。説明のかっこは全角（）にする
- `title` に、カードにする人物の名前を入れない (答えが分かってしまう)
- 時代の中では年の順に書く
- `npm test` が、書式・参照切れ・年の順・ふりがなのかっこ・タイトルの人物名を検査する

できごとや人物を追加・変更すると、その日以降の「今日のチャレンジ」の内容が変わります。

## 出題のしかた (`src/core/game.ts`)

1 回のゲームの 5 枚は、どちらが先か必ず決められるようにえらびます。

- 同じ年のもの (1185 年の「壇ノ浦の戦い」と「鎌倉幕府が開かれる」など) は、同じゲームに出さない
- 期間の中に入るもの (「弥生時代」と「邪馬台国の女王が魏に使いを送る」など) も出さない。期間どうしがさかい目でふれているだけ (縄文時代と弥生時代) ならよい
- 同じ人物は 2 つの列に出さない。織田信長が「桶狭間の戦い」と「本能寺の変」の両方に関係するときは、片方の列だけに信長のカードを出す。
  もう片方の列に信長を置いたときは、ミスにせず「そこにも関係があるけど、今回はほかのできごとの下」と教える
- 人物のいないできごと (縄文時代など) は 1 ゲーム 2 枚まで

- **今日のチャレンジ**: 日付から 7 つの時代のうち 5 つをえらび、時代ごとにならべかえた列の「2020-01-01 から何日目か」番目から 1 枚ずつ取る。いっしょに出せないときは、次の分をくり上げる
- **時代ごとの練習**: 時代のできごとをならべかえた列の前から 5 枚ずつ取る。いっしょに出せずに飛ばしたものは列の前に残り、次の回に先に出るので、一巡するまで同じできごとはほぼ出ない。「何回目か」(`round`) を途中経過といっしょに保存する

途中経過は、正しく置けたカードの id とミスの数で保存するので、ページを閉じても続きから遊べます。

## スタンプ・ポイント・スズメカード

- 今日のチャレンジを最後までやると 20pt (日付ごとに 1 回) とスタンプ 1 個。時代の練習はミス 3 回まででクリアすると 20pt (時代ごとに 1 回)
- 7 日連続するたびに 1000pt (とぎれたら数え直し)、その月の 1 日から末日まで全部そろうと、さらに 5000pt
- カードは 40pt から 3000pt までの 20 枚で、合計 28,420pt (値段はスズメの社会クイズと同じ)。むかしの時代のスズメから新しい時代へ、最後は「天下人の スズメ」
  - 今日のチャレンジを毎日やると、はじめの 5 枚は 2 週間以内 (2・6・7・7・14 日目) に手に入る
  - 全部集めるには、いちばん多くポイントをもらう人でも 89 日かかる
  - 値段を変えるときは、`tests/rewards.test.ts` の「カードの値段のバランス」が通ることを確かめる

ポイントは合計を保存せず、スタンプの日付とクリアの記録から毎回計算します (`src/core/rewards.ts`, `src/core/storage.ts`)。
カードの種類と値段は `src/data/cards.ts`、スズメと小物 (勾玉・烏帽子・兜・ちょんまげ・学生帽など) と背景の絵は `src/ui/sparrow.ts` にあります。

`npm run dev` を実行して `http://localhost:5173/cards.html` を開くと、全部のカードの表と裏面を一覧できます
(開発用のページで、`npm run build` の出力には入りません)。

日付は端末の時計 (日本時間に換算) で決まるので、時計を変えれば先の日のスタンプも押せてしまいます。

## ログインと記録の保存 (Firebase)

しくみはスズメの社会クイズと同じです。Google でログインした人の記録は Firestore に保存し、どのブラウザや端末でも同じ記録で遊べます。
ログインしない人の記録は、そのブラウザの localStorage (`rekishi:v1:…`) だけに保存します。

- 画面はいつも手元 (localStorage) の記録を読み書きする (`src/core/storage.ts`)。ログイン中の人の写しは `rekishi:u:<uid>:…`
- ログイン中は、書きかわった分を少しまとめてから Firestore に送る (`src/cloud/sync.ts`)。
  ログインしたとき・ページを開いたときは、Firestore の記録と手元の写しを合わせて、両方に書く (`src/core/merge.ts`)
- **Firebase の設定を入れていないビルドでは、ログインの入り口は出ず、Firebase のコードも読みこまれません**

| 記録 | 合わせ方 |
|---|---|
| スタンプの日付、クリアしたゲーム | 両方を合わせた集合 |
| 持っているカード | 両方を合わせる (同じカードは払った額の小さいほう) |
| ゲームの途中経過 | 練習の回が進んでいるほう。同じ回ならクリア済みを優先し、どちらも途中なら多く置いているほう (同じならミスの多いほう) |
| 音 | あとから変えたほう |

Firestore の形は小学生向けの学習アプリで共通で、このアプリの `appId` は `history-learning-jp` です。
ほかのアプリと同じ Firebase プロジェクトを使っても、記録はまざりません。

```
users/{uid}                                   その人の情報 (名前・メールアドレス・写真は保存しない)
users/{uid}/apps/history-learning-jp          スタンプの日付 (activeDays)、クリアしたゲーム (completed)、
                                              持っているカード (inventory)、設定 (settings: 音)
users/{uid}/apps/history-learning-jp/progress/{ゲームの id}   途中経過 (置いたカード・ミスの数)
```

設定値は `config.js` (手元) か、同じ名前の環境変数 (GitHub Actions では Variables) で入れます。`config.js` は `.gitignore` に入っています。

```js
const FIREBASE_API_KEY = '…';
const FIREBASE_AUTH_DOMAIN = '….firebaseapp.com';
const FIREBASE_PROJECT_ID = '…';
const FIREBASE_APP_ID = '…';
const GTM_ID = 'G-XXXXXXXXXX'; // アクセス解析 (入れなければタグは埋め込まない)
```

Firebase コンソールでは、Authentication で Google ログインを有効にし、承認済みドメインに公開先を足し、
Firestore のルールに `firestore.rules` の内容を設定します。ログインできないときの調べ方は、スズメの社会クイズの README を見てください。

### エミュレーターで動かす (開発用)

```sh
npx firebase-tools emulators:start --only auth,firestore --project demo-rekishi
FIREBASE_API_KEY=x FIREBASE_AUTH_DOMAIN=localhost FIREBASE_PROJECT_ID=demo-rekishi FIREBASE_APP_ID=x FIREBASE_EMULATOR=1 npm run dev
```

## 構成

- `src/core/game.ts` 出題 (今日のチャレンジ・時代の練習) と、カードを置いたときの判定
- `src/core/rewards.ts`, `src/core/storage.ts` スタンプ・ポイント・カードと、手元の記録
- `src/core/merge.ts`, `src/core/snapshot.ts` 記録を合わせる決まりと、Firestore に保存する形
- `src/cloud/` ログインと Firestore との同期 (Firebase に依存するのは `firebase.ts` だけ)
- `src/data/` できごと・人物・時代・カード
- `src/ui/` ホーム、ゲーム (`game.ts`)、年表ずかん、スタンプカード、カード、スズメの絵
- `tests/` データの検査、1 年分の今日のチャレンジと練習の出題、置いたときの判定、ポイント、記録の合わせ方、同期
